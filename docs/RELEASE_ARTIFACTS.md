# Release Artifact Standards

This document defines what constitutes a valid, deployable artifact for the MT5 AI/ML Trading Bot. Standardizing these artifacts ensures consistency, traceability, and safety across all environments.

## 1. Mandatory Artifact Components

Every release package generated by `scripts/package_release.sh` must include the following six components:

| Component | File/Format | Description |
| :--- | :--- | :--- |
| **Docker Image** | `image.tar.gz` | Exported Docker image for the specific version, allowing for offline deployment and traceability. |
| **Docker Metadata** | `docker_info.json` | Contains the Docker image name, tag, build date, and VCS reference (git SHA). |
| **Environment Template** | `.env.example` | The authoritative template for environment variables required by the specific version. |
| **Database Migrations** | `migrations/` | Full directory containing Alembic migration scripts to ensure schema consistency. |
| **Configuration Docs** | `CONFIG_REFERENCE.md` | Auto-generated reference of all Pydantic settings, types, and defaults. |
| **Release Notes** | `RELEASE_NOTES.md` | Version-specific change log extracted from the `[Unreleased]` section of `CHANGELOG.md`. |
| **Checksum Manifest** | `checksums.sha256` | SHA256 hashes of all files in the artifact for integrity verification. |

## 2. Artifact Directory Structure

The packaging process creates a versioned directory under `releases/`:

```text
releases/v<VERSION>/
├── image.tar.gz
├── docker_info.json
├── .env.example
├── CONFIG_REFERENCE.md
├── RELEASE_NOTES.md
├── checksums.sha256
└── migrations/
    ├── env.py
    ├── script.py.mako
    └── versions/
        └── *.py
```

## 3. Automated Validation

The `scripts/package_release.sh` script enforces the following validation rules:

1.  **Existence**: All six mandatory components must be present in the target directory.
2.  **Size**: All generated files must be non-zero in size (detects empty configs or logs).
3.  **Integrity**: The script performs a self-verification by running `sha256sum -c checksums.sha256` after generation.
4.  **Version Match**: The artifact directory name must match the `version` field in `pyproject.toml`.

## 4. Deployment and Verification

To verify an artifact before deployment, run the following command from within the release directory:

```bash
# Verify file integrity
sha256sum -c checksums.sha256

# Expected output:
# ./image.tar.gz: OK
# ./.env.example: OK
# ...
```

If any file fails verification (indicated by `FAILED`), the artifact is considered corrupted and must NOT be deployed.
