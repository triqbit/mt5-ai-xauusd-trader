# Runbook 04: Database Corruption Recovery

## Overview
The bot uses SQLite (`trades.db`) for operational logging, trade tracking, and risk audit trails. This runbook covers recovery from database corruption or unrecoverable malformation.

## Symptoms
- Logs: `sqlite3.DatabaseError: database disk image is malformed`
- Bot fails to start with `sqlalchemy.exc.DatabaseError`.
- Migration failures via Alembic during deployment.
- Health Check: `/health/readiness` reports `Database: FAILED`.

## Recovery Procedures

### 1. Attempt SQLite In-Place Repair
Try to recover as much data as possible from the corrupted file using the SQLite CLI:
```bash
# Export schema and data to a SQL dump, then re-import into a new file
sqlite3 trades.db ".recover" | sqlite3 trades_recovered.db

# Swap the files
mv trades.db trades.db.bak
mv trades_recovered.db trades.db
```
Verify the recovered file:
```bash
sqlite3 trades.db "PRAGMA integrity_check;"
```

### 2. Restore from Automated Backup
If in-place repair fails, restore the most recent stable backup generated by `scripts/backup_verify.sh`:

1. List available backups in the backup root:
   ```bash
   ls -ltr backups/db/
   ```
2. Identify the latest backup with a valid `.sha256` checksum.
3. Verify the backup integrity and content before restoring:
   ```bash
   # Navigate to the database backup directory
   cd backups/db/

   # Check checksum
   sha256sum -c trades_YYYYMMDD_HHMMSS.db.sha256

   # Perform a final integrity check on the backup file
   sqlite3 trades_YYYYMMDD_HHMMSS.db "PRAGMA integrity_check;"
   ```
4. Restore the file to the root directory:
   ```bash
   # From within backups/db/
   cp trades_YYYYMMDD_HHMMSS.db ../../trades.db
   ```

### 3. Re-initialize Database (Data Loss Accepted)
If no backups exist and repair is impossible, re-initialize the schema. **Note:** This results in total loss of historical trade logs and risk events. Refer to `docs/DATA_RETENTION_POLICY.md` for compliance implications.

1. Remove the corrupted file:
   ```bash
   rm trades.db
   ```
2. Re-run migrations to recreate the tables:
   ```bash
   alembic upgrade head
   ```

## Expected Outcomes
- `trades.db` is a valid, readable SQLite file passing `PRAGMA integrity_check;`.
- Application startup health checks pass for the Database component.
- The `TradeLogger` can successfully persist new signals and trades.

## Verification Commands
- **Integrity Check:** `sqlite3 trades.db "PRAGMA integrity_check;"`
- **Schema Check:** `alembic current`
- **Audit Verification:** `sqlite3 trades.db "SELECT count(*) FROM risk_events;"`
- **Health Check:** `curl http://localhost:8000/health/readiness`

## Prevention & Maintenance
- **Backups:** Ensure `scripts/backup_verify.sh` is running via a daily cron job.
- **Disk Space:** Monitor disk usage (`df -h`) to prevent partial writes.
- **Process Safety:** Never hard-kill the bot (`kill -9`) unless absolutely necessary; use `SIGTERM`.
