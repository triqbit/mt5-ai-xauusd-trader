# Runbook 04: Database Corruption Recovery

## Overview
The bot uses SQLite (`trades.db` and `audit.db`) for operational logging, trade tracking, and risk audit trails. This runbook covers recovery from database corruption or unrecoverable malformation.

## Symptoms
- **Logs:** `sqlite3.DatabaseError: database disk image is malformed`.
- **Startup Failure:** Bot fails to start with `sqlalchemy.exc.DatabaseError`.
- **Migration Failure:** Alembic cannot apply or revert migrations.
- **Health Check:** `/health/readiness` reports `Database: FAILED`.

## Recovery Procedures

### 1. Attempt SQLite In-Place Repair
If the database file is still accessible, try to recover data using the SQLite CLI:
```bash
# Export schema and data to a SQL dump, then re-import into a new file
sqlite3 trades.db ".recover" | sqlite3 trades_recovered.db

# Swap the files
mv trades.db trades.db.bak
mv trades_recovered.db trades.db
```
Verify the recovered file:
```bash
sqlite3 trades.db "PRAGMA integrity_check;"
```

### 2. Restore from Automated Backup (Recommended)
If in-place repair fails, restore the most recent stable backup generated by `scripts/backup_verify.sh`.

1. **Identify Backups:** List available backups:
   ```bash
   ls -ltr backups/db/
   ```
2. **Verify Backup Integrity:**
   Choose the latest backup and verify its SHA256 checksum:
   ```bash
   cd backups/db/
   sha256sum -c trades_YYYYMMDD_HHMMSS.db.sha256
   ```
3. **Restoration:**
   Copy the verified backup to the root directory:
   ```bash
   cp trades_YYYYMMDD_HHMMSS.db ../../trades.db
   ```
4. **Post-Restore Check:**
   Verify the restored file:
   ```bash
   sqlite3 trades.db "PRAGMA integrity_check;"
   ```

### 3. Re-initialize Database (Last Resort)
If no backups exist and repair is impossible, re-initialize the schema. **WARNING:** This results in the loss of historical trade logs and risk events.

1. Remove the corrupted file:
   ```bash
   rm trades.db
   ```
2. Re-run migrations to recreate the schema:
   ```bash
   alembic upgrade head
   ```

## Expected Outcomes
- `trades.db` and `audit.db` are valid SQLite files passing `PRAGMA integrity_check;`.
- Application startup health checks pass for the Database component.
- The `TradeLogger` and `AuditLogger` can successfully persist new records.

## Verification Commands
- **Integrity Check:** `sqlite3 trades.db "PRAGMA integrity_check;"`
- **Schema Check:** `alembic current`
- **Audit Verification:** `sqlite3 trades.db "SELECT count(*) FROM risk_events;"`
- **Health Check:** `curl http://localhost:8000/health/readiness`

## Prevention & Maintenance
- **Backups:** Ensure `scripts/backup_verify.sh` is running via a daily cron job.
- **Disk Space:** Monitor disk usage (`df -h`) to prevent partial writes due to full disks.
- **Process Safety:** Use `SIGTERM` for graceful shutdowns; avoid `kill -9` whenever possible.
