# Runbook 05: Failed Deployment Rollback

## Overview
This runbook provides standardized procedures for rolling back a failed production release. This includes reverting Docker image versions and, if necessary, performing database schema downgrades.

## Rollback Triggers
- High error rate (>1%) immediately after deployment.
- Critical failure in MT5 connectivity or order execution.
- Startup Health Check reports `FAILED` for core components.
- Unexpected trading behavior detected by the `ExecutionFilter`.

## Step-by-Step Rollback

### 1. Identify Last Stable Version
Refer to the `CHANGELOG.md` or the `release.yml` history on GitHub Actions to identify the previous stable version tag (e.g., `v1.2.2`). Check the manifest generated by `scripts/package_release.sh` for the specific Docker image digest.

### 2. Roll Back Docker Deployment
If using Docker Compose:
1. Update the `IMAGE_TAG` in your environment file or `docker-compose.yml`:
   ```bash
   export BOT_VERSION=v1.2.2
   docker-compose up -d
   ```
2. Or pull and run the previous stable image directly:
   ```bash
   docker pull triqbit/mt5-trader:v1.2.2
   docker stop mt5-trader
   docker run -d --name mt5-trader --env-file .env triqbit/mt5-trader:v1.2.2
   ```

### 3. Roll Back Database Migrations (If Required)
If the failed release included a database migration that is incompatible with the previous version:
1. Identify the current revision and the target revision:
   ```bash
   alembic current
   alembic history --verbose | head -n 20
   ```
2. Downgrade to the last known stable revision:
   ```bash
   alembic downgrade <stable_revision_id>
   ```
   **WARNING:** Downgrading may result in loss of data stored in newly added columns/tables. Review `migrations/` scripts before execution.

### 4. Verify Rollback Stability
1. Execute the system "doctor" script:
   ```bash
   python scripts/doctor.py
   ```
2. Verify application health:
   ```bash
   curl http://localhost:8000/health/readiness
   ```

## Post-Rollback Tasks
1. **Communication:** Notify the trading and engineering teams via Telegram/Slack about the rollback.
2. **Analysis:** Perform a Root Cause Analysis (RCA) to identify why the release failed and why the `pre-deploy-validation.yml` gate did not catch it.
3. **Fix:** Apply fixes and trigger a new release only after a successful staging verification.

## Expected Outcomes
- The system is restored to the previous stable state (Docker image and DB schema).
- P0/P1 alerts are resolved.
- Trading resumes (if appropriate) or is safely halted in a known stable state.

## Verification Commands
- **Image Version:** `docker inspect triqbit/mt5-trader --format '{{.Config.Labels.version}}'`
- **Migration Status:** `alembic current`
- **Health Check:** `curl http://localhost:8000/health/liveness`
