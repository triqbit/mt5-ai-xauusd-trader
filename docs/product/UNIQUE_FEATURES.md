# Institutional Differentiation: Unique Product Features

This document defines the high-value features that differentiate the MT5 AI XAUUSD Trader from generic retail bots. These features focus on institutional-grade transparency, risk management, and adaptive intelligence.

---

## 1. Pre-trade Intelligence Briefing

### What it is and why it matters
The **Pre-trade Intelligence Briefing** is a structured analytical report generated by the system the moment a trade signal is produced, but before it is dispatched to the execution engine.

In institutional trading, "execution" is the final step of a "deliberation" process. This feature provides the system with a "sanity check" layer that evaluates if the current market context (macro and regime) is actually conducive to the specific strategy being triggered. It transforms the "Black Box" into a "Glass Box."

### How it differentiates from generic trading bots
Generic bots execute blindly when a technical condition is met (e.g., EMA cross). The MT5 AI Trader, with this briefing, asks: *"I see a buy signal, but is the USD currently in a high-volatility regime due to an imminent FOMC release? Is the expected slippage on XAUUSD currently exceeding our risk threshold? Does the ensemble consensus agree, or is this a marginal signal?"*

### Architecture Outline
1.  **Intelligence Aggregator**: A service that queries the `EnsembleModel` (for consensus), `MacroSensitivity` (for event risk), and `RiskManager` (for current exposure).
2.  **Execution Quality Forecaster**: A module that analyzes recent `trade_logger` data to estimate expected slippage and fill probability for the current time-of-day and volatility.
3.  **Briefing Payload**: A structured object containing:
    *   **Regime Context**: Trending, Mean-Reverting, or Exhausted.
    *   **Macro Risk Score**: 0-100 based on the economic calendar and real-time yield correlations.
    *   **Model Consensus**: The distribution of "votes" among the ensemble members.
    *   **Execution Forecast**: Expected slippage and liquidity depth.
4.  **Integrated Gate**: A hook in `src/trading/execution.py` that evaluates the briefing against the active **Capital-Preservation Operating Mode**.

### Acceptance Criteria
| Category | Requirement |
| :--- | :--- |
| **Functional** | System must generate a briefing within 500ms of a trade signal. |
| **Functional** | Briefing must be persisted to the `trade_briefings` database table. |
| **Technical** | Payload must include `regime_id`, `macro_risk_score`, `model_consensus`, and `expected_slippage`. |
| **Operational** | Briefing must be deliverable via Telegram if `TELEGRAM_REPORTING` is enabled. |
| **Release Readiness** | Integration tests must confirm that trade execution is blocked if the briefing cannot be generated. |

### Implementation Lane
*   **Jules04 (Adaptive Intelligence)**: Lead on logic for Regime Context, Macro Risk Scoring, and Model Consensus.
*   **Jules01 (Core Development)**: Lead on the aggregator service, database schema, and execution hook integration.

### Dependencies and Constraints
*   **Dependencies**: Requires the `MacroSensitivity` module (FRED/YFinance) to be operational.
*   **Constraints**: Briefing generation must not exceed 1000ms to avoid stale pricing.
