# Audit Logging System

## Overview
The MT5 AI/ML Trading Bot includes a comprehensive audit logging system designed for enterprise compliance, regulatory auditing, and deep debugging. Every critical decision made by the system is attributable, timestamped, and traceable.

## Audit Log Schema
The audit logs are stored in the `audit_logs` table with the following structure:

- `id`: Primary key.
- `event_type`: Category of the event (e.g., `CONFIG_CHANGE`, `TRADE_BLOCKED`, `MODEL_PREDICTION`, `RISK_DECISION`, `OPERATOR_ACTION`, `DEPLOYMENT_EVENT`).
- `timestamp`: UTC timestamp of the event.
- `actor`: The component or person initiating the action (`system`, `operator`, `ai_model`, `risk_engine`, `release_pipeline`).
- `action`: A short description of the action taken.
- `status`: Outcome of the action (`SUCCESS`, `FAILURE`, `BLOCKED`).
- `details`: Human-readable summary of the event.
- `metadata_json`: Structured JSON data containing context-specific information (e.g., decision chains, prediction scores).

## Tracked Events

### 1. Configuration Changes
Logs all changes to trading parameters, whether at startup or during runtime.
- **Metadata**: Field changed, old value, new value, and reason.

### 2. Blocked Trades
Whenever the risk engine prevents a trade from being executed, a detailed log is created.
- **Metadata**: Signal ID, primary rejection reason, and the state of all risk filters at the time of rejection.

### 3. Model Predictions
Logs every prediction generated by the AI ensemble.
- **Metadata**: Symbol, direction, confidence score, and individual model contributions.

### 4. Risk Decisions
Records the complete evaluation of the 6-layer risk filter cascade for every signal.
- **Metadata**: Status of each filter (Circuit Breaker, Daily Loss, Max Positions, Symbol Allocation, Min Confidence, Risk-Reward).

### 5. Operator Actions
Logs manual interventions such as emergency halts or manual overrides.
- **Details**: Description of the action and reasoning provided by the operator.

### 6. Deployment Events
Logs when the application starts, including the version and environment mode.
- **Metadata**: Version number, environment (live/demo/backtest).

## Implementation Details
The system is implemented in `src/core/audit_log.py` using SQLAlchemy. It is integrated into the core trading loop in `main.py` and the risk validation logic in `src/trading/risk_manager.py`.

## Querying Audit Logs
Audit logs can be queried directly from the database for post-incident review:

```sql
-- View all blocked trades and their reasons
SELECT timestamp, details, metadata_json
FROM audit_logs
WHERE event_type = 'TRADE_BLOCKED'
ORDER BY timestamp DESC;

-- Review recent configuration changes
SELECT timestamp, details
FROM audit_logs
WHERE event_type = 'CONFIG_CHANGE'
ORDER BY timestamp DESC;
```
