# Data Retention Policy - MT5 AI/ML Trading Bot

## 1. Purpose
This policy defines the retention periods and disposal requirements for operational data generated by the MT5 AI/ML Trading Bot. It ensures compliance with financial regulations while optimizing storage and system performance.

## 2. Scope
This policy applies to all data stored in the application database (PostgreSQL/SQLite), log files, and exported artifacts (backtest results, performance reports).

## 3. Retention Schedule

| Data Category | Table / Location | Retention Period | Action after Expiry |
| :--- | :--- | :--- | :--- |
| **Trade Records** | `trades` | 7 Years | Archive to Cold Storage |
| **Model Signals** | `model_signals` | 1 Year | Purge |
| **Risk Events** | `risk_events` | 2 Years | Purge |
| **Performance Metrics** | `performance_metrics` | 3 Years | Archive Summary, Purge Details |
| **Application Logs** | `logs/*.log` | 90 Days | Delete |
| **Market Data (OHLCV)** | `market_data` | 5 Years | Archive |
| **Market Data (Ticks)** | `tick_data` | 90 Days | Delete |
| **Backtest Results** | `data/backtests/` | 1 Year | Delete |

## 4. Archival Rules
- **Trade Records**: After 7 years, trade records must be exported to a compressed format (CSV/JSON) and stored in a secure, long-term archival service (e.g., AWS S3 Glacier).
- **Performance Metrics**: Annual summaries should be retained indefinitely; granular periodic snapshots can be purged after 3 years.
- **Audit Logs**: All database audit trails (created_at, updated_at) must be preserved for the duration of the record's lifetime.

## 5. Automated Purging
- A cleanup script (`scripts/data_cleanup.py`) runs periodically to enforce these retention windows.
- **IMPORTANT**: The script implements the **Delete** and **Purge** actions.
- For categories requiring **Archive** (Trade Records, OHLCV), users must perform archival/export *before* the retention period expires. The script will permanently remove data older than the retention window regardless of archival status.
- Safe deletion logic must include integrity checks to ensure no open trades or active signals are prematurely removed.

## 6. Auditability vs. Storage Control
- **Preserve for Audit**: Execution tickets, fill prices, P&L, risk approvals, and regulatory timestamps.
- **Rotate for Storage**: Debug logs, raw model inference tensors (if logged), and transient market heartbeat signals.

## 7. Compliance
This policy is designed to align with standard financial record-keeping requirements (e.g., SEC Rule 17a-4, MiFID II) which typically mandate 5-7 years of trade record retention.
